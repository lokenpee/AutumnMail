# 秋招邮件 Agent P0 开发清单 v0.1

> 关联文档：`docs/requirements-analysis.md`、`docs/data-model.md`、`docs/technical-architecture.md`
> 说明：本文只覆盖 P0，也就是能形成可验证 MVP 的最小闭环。UI 原型后置，先完成后端、数据层和可替换接口。

## 1. P0 成功定义

完成以下闭环即可认为 P0 达标：

1. 用户可以安全配置 163 邮箱，不把授权码写入源码或模型上下文。
2. 系统可以按日期同步历史邮件，并增量同步新邮件。
3. 同一邮件重复同步不会产生重复记录。
4. 邮件可以被规范化、去重、归属公司、分类并抽取 DDL。
5. 用户可以在 API 层完成日期筛选、公司聚合、分类修正、完成状态修改和 DDL 修改。
6. 日历查询可以按日期返回 DDL 数量、明细和原邮件链接。
7. 人工修正不会被自动处理覆盖。
8. 后端在真实小规模邮件集上可稳定运行，并能通过自动化测试。

## 4. P0 验收清单

- [ ] 可以安全连接 163 邮箱并完成授权码验证。
- [ ] 可以按日期范围同步历史邮件。
- [ ] 可以持续同步新邮件。
- [ ] 单封邮件失败不会中断整批同步。
- [ ] 重复同步不会产生重复邮件。
- [ ] 邮件可以按公司和岗位聚合。
- [ ] 每封求职邮件有主分类，低置信度进入复核。
- [ ] 人工修正公司、分类和 DDL 后不会被自动结果覆盖。
- [ ] 测评和笔试可以标记完成或取消完成。
- [ ] 测评和笔试可以添加、修改和清除 DDL。
- [ ] 日历可以按天返回未完成和已完成 DDL。
- [ ] 日历明细可以追溯到对应邮件。
- [ ] 日期范围在所有查询中一致生效。
- [ ] 日志和模型上下文中不会出现邮箱授权码。
- [ ] 本地数据库可以备份、重置和重新初始化。

## 5. 原型之后的接口冻结点

UI 原型不需要阻塞后端开发，但以下接口应在原型确认后冻结：

- 邮件列表筛选参数。
- 邮件详情返回结构。
- 公司聚合返回结构。
- 日历日期聚合结构。
- 分类修改和 DDL 修改的请求结构。
- 待确认队列的展示字段。
- 跳转 163 原邮件所需的链接字段。

在此之前，后端保持领域模型和 API 语义稳定，不绑定具体组件和页面布局。
